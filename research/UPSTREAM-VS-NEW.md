# Upstream vs new: honest comparison

Upstream = nextlevelbuilder/ui-ux-pro-max-skill @ `4aad058`. New = `design-engineering/` v1 (2026-09-08). Numbers come from `research/BENCHMARK-RESULTS.md` (generated by `evals/benchmark_upstream.py`) and `evals/run_evals.py`.

## Retrieval

| Aspect | Upstream | New | Evidence |
|---|---|---|---|
| Mean relevant-term coverage over 18 benchmark queries | 0.200 | 0.922 · see BENCHMARK-RESULTS.md for the guidance bundle | research/benchmark-results.json (method v2, re-run 2026-09-16 idle on the Phase 6 c4 freeze; Phase 5 c2: 0.915 search / 0.927 bundle), rendered in BENCHMARK-RESULTS.md |

| Task-mode awareness | none beyond three CLI flags | ten modes detected and boosted; audit/accessibility rank rules over layouts | retrieval evals |

| Cold latency per query (subprocess incl. interpreter start, both measured identically, 7 reps) | 113 ms median | 196 ms median (3–4 ms warm in-process) | benchmark method v2 re-run 2026-09-09 (both faster than the Phase 2 run on the same machine: less background load); upstream is faster cold because it loads one CSV, we load 232 records and build the field index |
| Where upstream was stronger | media query (0.38 vs 0.38 tie): upstream's style rows mention "rail/focus" vocabulary once; ours ties because the term list includes "pivot", which only the pattern record carries at k=3 | — | benchmark "honest list": none higher, one tie |

Caveat: the benchmark scores topical fit of returned text against human term lists, not design quality; the term lists were written by the same author as the new records. The direction of the result (platform-aware vs. platform-blind) is not in doubt; the magnitude is indicative only.

## Knowledge model

| Aspect | Upstream | New |
|---|---|---|
| Records | ~1,000 rows across 35 CSVs (747 KB is a Google Fonts dump) | 220 JSONL records, ~250 KB |
| Dimensions per record | product type, free-text "best for/avoid", style columns | intent, platform, input, product, screen, density, risk, compatibility, provenance, per-stack implementation, fingerprint, rank |
| Relationships | one join key (Product Type) | id references (`compatible`/`incompatible`), slot composition, fingerprint fragments |
| Provenance | file-level JSON | per record, seven classes; taste is labelled as taste |
| TV / remote coverage | 2 mentions of "dpad" | 25+ TV-tagged records, a TV platform file, two TV stack files |
| Desktop-native coverage | API guideline rows (x:Bind, MVVM) | desktop platform file, WinUI/WPF/Avalonia stack files, desktop rules and directions |

Upstream is stronger in breadth of *framework API* tips (22 stack CSVs of "use x:Bind / hoist state") and in the sheer number of style/palette/font rows. The new skill deliberately does not replicate that: framework API advice belongs in framework docs (and Claude knows it), and palette/font rows encouraged style-first decisions.

## Output quality levers

| Risk | Upstream | New |

| Generic SaaS dashboard | structurally encouraged (product label → landing pattern + palette) | anti-pattern surfaced for any dashboard request; direction derives navigation/density/layout from task; "no cards" honoured |

## Engineering

| Aspect | Upstream | New |
|---|---|---|
| Sources of truth | 3 mirrored trees + template-generated SKILL.md for other platforms | 1 directory |
| Dependencies | Python stdlib (+ npm CLI, Playwright for e2e) | Python stdlib only |
| Validation | 53 KB `validate_data.py` + CI sync check | `validate_skill.py` (schema, refs, lexicon alignment, eval refs, frontmatter limits) |
| Tests/evals | 160 unit tests (mostly non-emptiness), 90-case graded relevance fixture | 109 eval cases in 9 suites (activation, retrieval, platform, brand, accessibility, anti-generic, project, greenfield, tools) + benchmark harness |
| Determinism | search, routing, decision rules | search, classification, direction, contrast, token validation, fingerprint comparison, project inspection |

Upstream advantages worth acknowledging: a human-graded relevance fixture with held-out splits and a documented approval process (ours has graded cases but no held-out split); multi-assistant distribution; catalog refresh workflows for fonts/icons; a public gallery.

## Phase 2 addendum (2026-09-08)

The comparison above uses the author-written benchmark set. Phase 2 added an independent held-out set (145 cases) and an independent activation set (180 prompts); results and their limits are in `research/PHASE2-RESULTS.md`. In short: classification generalises (platform recall 123/145, negatives 138/145), guidance retrieval against an independent reviewer's expected concepts did not in Phase 2 (mean token-level concept recall 0.184; Phase 3's concern-driven bundle raised the same historical set to 0.336 and a blind v2 set is reported in `research/PHASE3-RESULTS.md`), and upstream was not re-scored on that set because its output has no comparable requirements layer.

## Eval results at v1

108 of 109 cases pass. The failing case, `winui-erp-grid`, expects the universal keyboard rule in the top 5 for "WinUI desktop ERP data grid with keyboard shortcuts"; it ranks 6th behind ERP-specific table/layout records that also match the stated keyboard input. The case is kept as a known ranking limitation rather than edited: universal rules can still be edged out of a 5-item list by many product-specific records that share the same structural signals. Two other cases received dated, justified threshold adjustments (recorded in their `note` fields).
