### Horizontal rails (rows of content)  `layout-rails`  [pattern/layout; layout/platform] score 0.732 · platform-standard
Each rail has a visible title, focused item scrolls to a fixed pivot (about 20–30% from the left) rather than centring, rails remember their last focused index when returning, row heights are consistent within a rail, and off-screen items are partially visible to signal continuation. Lazy-load rails and images; never render every rail on first paint. Keep the safe margin (~5% / 48 dp horizontal, 27 dp vertical at 960×540 dp).
- use when: TV browsing of categorised content: vertical axis moves between categories, horizontal axis moves within a category. The default TV home structure.
- avoid when: Fewer than ~8 items total (use a grid or list), or content that must be compared side by side.
- compose-tv: LazyColumn of LazyRow (Compose Foundation ≥1.7 has focus-aware scrolling); wrap each row in focusRestorer(); set LocalBringIntoViewSpec for the pivot; TvLazyRow is deprecated.
- incompatible with: layout-single-column, layout-table-first, layout-three-pane, layout-dashboard-grid, nav-top-bar, nav-left-rail
- why: lexical 0.469, structural 0.92 (platform tv, input remote (stated), secondary mode, product media, screen home, density medium)

### TV side navigation (collapsible drawer)  `nav-tv-side`  [pattern/navigation; navigation/platform] score 0.677 · platform-standard
Collapsed icon strip on the left that expands to icons+labels when focus enters it; pressing LEFT from the first item of any rail moves focus into the drawer, RIGHT returns to the last focused content item (focus restoration is mandatory). Back from content returns to the drawer, Back from the drawer exits or goes Home. Never require UP to reach navigation from deep in a page.
- use when: TV apps with 4–8 sections (Home, Live, Movies, Series, Search, Settings) where the vertical axis is free for section switching and the horizontal axis is used for browsing rails.
- avoid when: Two or three sections (use top tabs), single-purpose players, or when content rails need the full width and the drawer would fight with left-edge focus.
- compose-tv: NavigationDrawer/ModalNavigationDrawer from androidx.tv.material3; wrap content in focusRestorer() so RIGHT returns to the previous item; give the drawer a focusGroup.
- incompatible with: nav-top-bar, nav-left-rail, nav-bottom-tabs, nav-tv-top-tabs
- why: lexical 0.398, structural 0.84 (platform tv, input remote (stated), secondary mode, product media, density medium)

### Immersive hero + rails  `layout-immersive-rails`  [pattern/layout; layout/platform] score 0.631 · platform-standard
Backdrop crossfades on focus change with a debounce (~300 ms) so scrubbing across a rail doesn't thrash decodes; a scrim gradient guarantees text contrast over any image; the hero text block sits in the safe area with title, one line of metadata, and a short synopsis; the first rail is partially visible so users know to press DOWN. Provide a reduced-motion path with a static backdrop.
- use when: Media apps that want the focused item's artwork to fill the background while rails sit below; strongest when artwork quality is high and consistent.
- avoid when: Poor or inconsistent artwork, catalogues where text metadata matters more than imagery, or low-end devices where large image decode causes jank.
- compose-tv: ImmersiveList is deprecated; build with a Box(backdrop AsyncImage with Crossfade) + LazyColumn; use snapshotFlow on focused item with debounce.
- incompatible with: layout-rails, layout-single-column, layout-table-first, surface-bordered-panes, nav-top-bar, nav-left-rail
- why: lexical 0.321, structural 0.92 (platform tv, input remote (stated), secondary mode, product media, screen home, density medium)

### TV: predictable BACK  `tv-back-behavior`  [rule/navigation; navigation/platform] score 0.609 · platform-standard
BACK closes the topmost layer (player controls → player → detail → home → nav → exit); in a rail-based home, BACK from content first moves focus to the navigation (side nav or top tabs) and scrolls to top, then exits. Deep-linked entries still unwind to the app home. Splash screens are never in the back stack.
- use when: Every screen and overlay.
- avoid when: Never show an on-screen Back button (the remote has one); never trap the user in an exit-confirmation loop.

### Mini player / picture-in-picture state  `comp-mini-player`  [component/player; component/platform] score 0.568 · platform-standard
The mini player is a single focusable/tappable region anchored to a corner (TV: bottom-right inside the safe margin, never over the focused rail; mobile: bottom above the tab bar; web: bottom-right) with the title (one line, truncated with a full title on focus), live/progress indicator and exactly two actions (expand, close); on TV, SELECT expands to the full player and BACK from the full player returns to the mini state with focus restored to the element that was focused before; playback state (playing/paused/buffering/error) is shown with an icon plus text, and the audio keeps playing while the UI is navigated; the region is excluded from the rail's D-pad focus loop except through an explicit UP/RIGHT move; never autoplay audio from a mini player on page load on web.
- use when: Playback continues while the user browses (home rails, EPG, queue) on TV, or while navigating a mobile/web app.
- avoid when: Content that must not play in the background (paid live events with strict windows) or when the platform provides system PiP that the app should adopt instead.
- compose-tv: Box aligned BottomEnd with padding 48.dp; focusProperties { up/left = FocusRequester.Default }; BackHandler ordering: full player → mini → home.
- compose: Use PictureInPicture params when the app is backgrounded; in-app mini via a Scaffold bottom slot above the NavigationBar.
- why: lexical 0.28, structural 0.92 (platform tv, input remote (stated), mode audit, product media, screen home)
