## Classes, evidence, and what changed

1. **Inspector false positives (3 cases, highest impact).** `ListView` matched the D-pad regex (`|isTV` under `re.I`) and made every WinUI/WPF/Avalonia project a TV; every Apple project was tagged mobile; a leanback-only Android app kept mobile from its Compose dependency; an Android `app/` module read as a Next.js app router; plain HTML/CSS sites had no stack. Result: AMBIGUOUS statuses, TV rails and safe-area guardrails on a desktop grid, wrong density. **Fixed** (`inspect_project.py`; regression `reg-listview-is-not-tv`, `reg-tvos-project-not-mobile`).
2. **Vocabulary misreads (4 cases).** "outdoor gear" → outdoor environment; "in the store" → e-commerce product; "invoice" → finance product with high density; "on phones" for a website → two competing platforms (AMBIGUOUS); one UI term plus a UI framework word → AMBIGUOUS activation. **Fixed** in the lexicon (environment phrases need usage wording, bare `store` removed, `invoice` removed from finance, energy/utility/facility vocabulary added, "which button" problem statements), `requirements_status` (web + mobile/tablet is responsive web) and activation (stack word breaks a tie only with a UI term and no non-UI term; proxy precision unchanged 0.987, recall 0.987 → 1.0).
3. **Task-specific rules starved by the cap (5 cases).** `mobile-keyboard-ime`, `shared-device-privacy`, `cta-single-primary`, `anti-hover-only-actions`, `tv-back-behavior`, `data-tables-numeric` scored well in `search` but never entered the bundle because generic platform concepts filled it first, and same-category core picks pruned the most specific record (`comp-data-entry-grid`). **Fixed**: high-relevance rules (≥ 0.75 × top, lexical ≥ 0.4) become guardrails before coverage; coverage is a global greedy set cover over required demands; a same-category core record joins when it adds uncovered concepts; a masking concept distinguishes sensitive-data privacy from kiosk hygiene (regressions `reg-task-specific-rule-not-starved`, `reg-kiosk-privacy-in-bundle`, `reg-same-category-core-adds-concepts`).
4. **Direction slots contradicting guardrails (6 cases).** Elevated/glass surfaces for outdoor field use, poster (media) cards for banking and inspection lists, hero imagery on a kiosk, medium density with 16 px body on a kiosk, dark-first colour on a light-first codebase, command-palette navigation for a WPF grid. **Fixed in part**: product-fit guard (a niche pattern loses to a generic alternative within 25 % when the product is unknown or different), environment surface guard, low density for kiosk/outdoor, new invariants (outdoor surfaces, non-media poster cards, kiosk medium density, TV light-first colour). **Not fixed**: the direction cannot see the codebase's existing navigation model or theme polarity because the inspector does not extract them; documented as a limitation.
5. **Knowledge gaps (7 cases).** PDP and one-page checkout, plan comparison / seat management / invoice history, mini player, single-Tab-stop grids, WPF DataGrid pitfalls, column priority for narrow windows, next-episode prompt, Siri Remote gesture model, on-screen keypad for kiosks, accessible-mode reach zones, photo-capture field, tri-state checklist. **Added** five evidence-backed records with development cases (`comp-product-detail-page`, `comp-checkout-one-page`, `comp-plan-comparison`, `comp-mini-player`, `grid-single-tab-stop`) plus the WPF pitfalls in `stacks/wpf.md` and column-priority vocabulary on `desktop-window-resizing`. Left open (single occurrence, no second source): kiosk keypad, reach zones, photo capture, tri-state checklist, next-episode prompt, Siri gestures.
6. **Requirements misses not yet modelled (5 cases).** Screen and job extraction is thin (a checklist read only as a form; billing page components limited to settings/table; `jobs` empty for manage/download/report-hazard); risk `low` for hazard reporting. Partially addressed (checklist → list component, hazard/medication → high-risk jobs); the rest is documented as future work.
7. **Tooling limits (all cases).** No Gradle wrapper, Xcode, or Flutter on the machine: four cases rendered HTML twins and reviewed native code statically. `tokens.py scale` produced sizes below the platform floor (now clamped). Playwright `networkidle` never settles on a Next production page (agents used `load` + settle). The protocol referenced a non-existent `tokens.py check` (corrected to `validate`). The WinUI fixture referenced a NuGet package id that does not exist (corrected).
8. **Concurrency caveat.** Skill files were edited (concept labels, rules) while the first eight cases ran; three agents re-ran their skill commands afterwards and found identical records and slots, only `covers:` annotations added. The recorded verdicts therefore describe the skill within the 00:28–00:40 window; the frozen build (`research/runs/phase3-freeze.json`) includes the fixes derived from these findings.

## Reading the numbers

First-render defects halved after one or two guided iterations, but 36 remained across nine cases, mostly cosmetic or scope items (fonts not self-hosted, light theme only, twin fidelity). The skill's measurable contribution was: mode and platform classification (once the inspector bugs were removed), the platform guardrails (safe area, focus, targets, states), and the deterministic checks (`tokens.py contrast` caught real contrast failures in five cases). Its weakest point remains the visual direction, which is chosen without seeing the codebase's actual navigation and theme.
